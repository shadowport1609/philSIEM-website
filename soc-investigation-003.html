SIMULATED TRAINING CASE · SOC-003 · SSH authentication anomaly

Simulated SSH authentication failures

An external documentation-range source makes repeated SSH authentication attempts against a fictional Linux host. The available evidence supports attempted password guessing, not confirmed compromise.

SIMULATED · NOT A REAL INCIDENTINITIAL SEVERITY: MEDIUM
Training-data notice: All events, timestamps, hosts and indicators below are fictional. IPs use documentation-only address ranges and the domain uses an invalid example suffix. No real attacker or compromise is asserted.

Investigation brief

Objective

Determine what the provided evidence supports, what remains unknown, and which next steps are proportionate.

Evidence scope

A deliberately small synthetic sample. There is no endpoint access, full SIEM dataset or independent threat intelligence.

Analyst posture

Validate the signal, seek corroboration, document confidence and avoid treating indicators as identities.

Findings and limitations

Supported assessment

No successful authentication appears in this limited sample. Absence from the sample does not prove no compromise occurred elsewhere.

Recommended next steps

Check complete authentication logs and successful sessions; verify source is not authorised testing; rate-limit SSH and enforce key-based authentication where appropriate.

Learning outcomes

This exercise demonstrates a repeatable SOC workflow: validate the detection, construct a timeline, identify missing evidence, assess risk and recommend proportionate actions. The narrative is a worked training example, not a report from an actual incident.
